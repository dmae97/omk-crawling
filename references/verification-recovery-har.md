# 수집 복구·HAR 분석 검증 (2026-09-12)

이 문서는 첫 단계의 기록이다. 이후 변경과 현재 검사 결과는
[엔진 통합 검증](verification-engine.md)을 참고한다.

## 범위

- 웹: `omk_crawl/router.py`, `route_engine.py`, `retry_after.py`.
  일시적 HTTP 오류 재시도, 서버 대기 지시, 비동기 대기, 인증·요청 제한 종료를 검증했다.
- HAR: `omk_crawl/har.py`, `tools/har_tool.py`, 공개 API·레지스트리·CLI 연결.
  기본 정보 제한, 선택적 JSON 본문 추출, 입력 크기 제한과 부분 실패를 검증했다.
- 기존 미커밋 작업을 기준으로 수정했고, 다른 기능의 변경을 되돌리지 않았다.
  커밋·게시·배포와 전역 패키지 설치는 수행하지 않았다.

## 자체 리뷰와 한계

- 인증 응답보다 앞선 큰 차단 페이지를 반환하던 문제를 수정했다.
  실패한 unsafe method는 재시도·어댑터 전환을 하지 않는다.
- HAR 파싱은 네트워크를 호출하지 않는다. URL 경로와 명시적으로 포함한 응답 본문은
  개인정보를 포함할 수 있으므로 익명화 결과로 취급하면 안 된다.
- 라우터 제한은 개별 어댑터 내부 요청 수나 전체 실행 시간 제한이 아니다.
  실행 중인 동기 작업을 asyncio 취소로 강제 종료하지 않는다.
- 대상 파일의 엄격 타입 진단에는 Any·미지정 타입 등의 경고가 남아 있다. 위 타입 검사는
  오류 수준 검사이며 경고까지 모두 해소했다는 뜻이 아니다. 설정이나 검사 규칙은 바꾸지 않았다.
- LSP 전체 스캔은 대상 9개 중 확인 완료 0개로 끝났으며 신규 모듈 미탐색 등의 캐시 오류를
  반환했다. 마지막 세션 검사에도 캐시 오류 6건이 남았다. LSP는 미확인으로 남기고
  독립 타입 검사·실행·wheel 검증으로 대조했다.
- 라이브 사이트 차단 통과율, 실제 Android/iOS 기기, Python 3.10/3.11/3.13 및 전체
  코드 커버리지 수치는 이번 작업에서 측정하지 않았다. 실행 환경은 Python 3.12였다.
